# 交付、阶段判断与论文贡献边界

## 一、本轮完成应看到什么

1. 一张旧新结论对照表：哪些数字有效、哪些需修复、修复后是否变化。
2. 少数多基因程序卡及逐患者数据，通常不超过十张，不为凑数保留垃圾候选。
3. 外部复现与增量预测的真实结果；目标不可测或测试失败须有解释。
4. 有适用目标时的隐藏区域/结构测试，或明确说明还缺哪个不可替代条件。

全量 registry 仍保留作账本，但不能替代以上四项。

## 二、建议产物与表头

路径统一在 `infra/r16/recovery_20260918/`。这里给出最小字段，可按实际增补，不要求构建新的数据库服务。

### `old_vs_new_conclusions.tsv`

`result_id, legacy_decision, old_artifact, new_artifact, problem_type, change_in_estimate, change_in_interpretation, scope_remaining, unresolved_limitations`

### `program_definitions.json`

每个程序包含：`program_id, source_candidates, discovery_patients, gene_weights, input_genes, readout_genes, direction_rule, normalization_rule, nuisance_rule, geometry_definition, coverage_policy, frozen_for_external_at, definition_hash`。

输入基因与读出基因必须可机器检查分离；没有外部冻结时该字段为空，不能随意填一个过去时间。

### `program_patient_effects.tsv`

`program_id, cohort, patient_id, section_count, evaluable_spots, gene_coverage, molecular_coherence, raw_spatial_effect, adjusted_spatial_effect, incremental_error_reduction, status, failure_reason`

患者表保存全部患者，不像旧 Lane B 那样只截取前十个 ID。切片表另存，不混样本层次。

### `external_replication.tsv`

`program_id, cohort, cancer_context, n_patients_total, n_patients_evaluable, molecular_replication, spatial_replication, incremental_prediction, adaptation_mode, effect_estimate, ci_low, ci_high, p_or_q_if_valid, exposure_notes, limitations`

p 或 q 不适用就留 NA 并写原因；不能把中位单片 p 填到 cohort p。各层证据单独列，不用一个“REPRODUCED”抹平所有层次。

### 程序卡（Markdown + PNG/SVG 图）

一张卡只回答一个程序：它可能代表什么，定义是否多基因，哪些患者支持，空间形状是什么，粗组成之外剩多少，外部是否复现，预测是否有增量，最强替代解释是什么。

图建议包括原始/调整后图、技术基线图、分离基因子集的一致性、逐患者效应、外部同一坐标定义下的曲线或图例。空间坐标没有真实单位时明确用跳数/相对尺度，不印假 µm。允许展示失败样本，不只挑最漂亮切片。

### `final_decision.md`

先用日常语言给结论，后附数据表。必须标明：当前支持哪个 H，哪个仅有线索，哪个未测试；是否值得继续反演，或只保留场状态预测；哪些附加资源确实不可替代。只提最多两个下一步实质方向。

## 三、阶段判断，不设置“必须阳性”的施工门槛

| 结果 | 判断 | 下一步 |
|---|---|---|
| 纠错后仍有多基因空间程序，独立队列支持，增量预测也成立 | 继续原目标，有实质抓手 | 针对最强目标做隐藏结构/缺失区域实验 |
| 程序外部复现，但只代表组成或没有增量信息 | 描述性结果，不能冒充原目标 | 保留结果；仅在有明确新机制解释时再探索 |
| 只有场预测有增量，结构定位不成立 | 可保留场状态信息主张 | 不写隐藏结构或三维重建 |
| 所有候选在足够功效下被基线解释或外部失效 | 收缩路线，停止扩大模型 | 形成适用边界/负结果；不靠换名字救 claim |
| 数据覆盖、null、样本量不足 | 当前不可判定 | 说明最小缺口；没有授权不扩数据，其他可做任务继续 |

“足够功效”针对具体最小有意义效应 δ：例如某一实际预测误差减少或定位误差改善。δ 应根据任务基线和实际用途解释，不用全项目通用 0.5SD 统一杀所有候选。CI 包含零只能说明证据不确定；若要排除有价值效应，需报告区间上界低于有意义 δ 等更具体证据。

## 四、发表层次应争取什么

**不够：** 六轴均有 Moran 显著；许多算法产生相近 cluster；找到了已知分泌/上皮/基质基因；同一 score 在三个分位阈值下 Jaccard 为 0.71；191 个基因各有空间残余。

**更有价值：** 现有分子活动在不同组成/组织背景中呈现可复现的空间组织，且该组织对独立读出提供可迁移的增量信息；进一步明确哪些目标可以只凭可见外围推断，哪些根本不可识别。

**更强但不作为本轮必做：** 两类不同场的可分离反演，真实邻近平面信息，主动选择切片/ROI 的收益。

空间因子表示、细胞身份/活动拆分、邻域增强本身都有成熟先例。[L01、L02、L04] 本轮应将其作为工具，避免把换一种表示当最终贡献。可发表性仍取决于实际效应、独立性、科学解释与任务难度；本包不承诺期刊层次或阳性发现。

## 五、验收测试

本包已经运行的只有 `diagnostics/` 中的 12 个微型数学/软件测试。接入真实流水线时，至少补下列回归覆盖：

- PC 符号翻转、次序变化、定向平均；旋转不变性只在声明支持的子空间量上检查。
- 观察与每次 null 使用同一聚合算子；patient ID 重复不能增加独立样本数。
- remap 诊断传播到 artifact；不合格近似 null 不能静默标为有效检验。
- marker/程序/读出基因防自包含；训练/验证/隐藏区域的统计量防泄漏。
- 阴性窗与阳性窗同样生成；隐藏值改成任意数不改变输入特征与预测。
- 退役 ILC 不被意外使用；缺失基因、barcode 不齐、全零程序有显式输出。
- 新 registry 派生不删除历史记录；新旧候选有可追踪映射。

这些测试服务于具体结论，不要求先补齐整个仓库所有历史测试才能探索。实际运行哪些测试、通过多少、哪些未测，写进 `validation_report.md`。
